A　以資源為中心，看 FSM 如何關聯

適合理解溝通

左側是寫入來源，右側是讀取用途。點節點查看實際位置與 function 路徑。

看得清楚
某個資源連接了哪些 FSM，以及誰寫、誰讀。
閱讀代價
同一資源被很多 FSM 使用時，圖會變長；因此先按 FSM 聚合，位置明細點開才看。

B　以 FSM 為中心，看狀態與資源

適合初學理解

點狀態看讀寫資源；切到轉態條件後，點連線編號看條件，以及條件變數由誰寫入。

狀態與轉態皆是假資料。每個轉態編號對應一筆已生成的條件讀取；未模擬優先順序及完整狀態機語意。

看得清楚
某個狀態會碰哪些資源，轉態條件依賴誰提供資料。
閱讀代價
跨 FSM 比較需要切換；大量轉態先依起點、終點合併顯示，編號清單保留每一條。

C　以更新位置為中心，逐層追查

適合定位問題

操作 → 實際寫入位置 → FSM／狀態 → function 路徑。同一行寫入不因多個來源重複計數。

暫存器的整體寫入另列一組，避免和單一 bit 的設定／清除混淆。

看得清楚
多個更新點的操作差異，以及每個位置的所有觸發來源。
閱讀代價
整體溝通關係不如圖形直觀；全部展開仍會很長，平常逐支展開較合適。

01　資源使用總覽

W 寫入 · R 動作讀取 · T 轉態判斷讀取。點欄名看全部來源，點格子聚焦該 FSM。收合周邊的數字是使用的資源數。

02　選取資源 / 更新位置優先

實際寫入位置 同一位置只列一次

誰讀取、拿來做什麼

寫入位置 ≠ 呼叫來源數。同一個寫入點可能由多個 FSM 觸發。讀寫並列呈現靜態關聯，不代表執行順序或已確認的競態。
